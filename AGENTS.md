## Durable Instructions for Future Codex Work

RenewalOS is a synthetic public portfolio project. Treat the current repository as design-first until the user explicitly asks for later implementation stages.

## Working Rules

- Inspect existing documents before changing project scope.
- Maintain traceability from future source data to KPIs and decisions.
- Never create fake metrics, fabricated results, invented business impact, fake screenshots, or unsupported model-accuracy claims.
- Create small, reviewable changes.
- Run relevant validation before claiming work is complete.
- Keep synthetic-data labels visible in documentation, examples, metrics, and future outputs.
- Document assumptions, incidents, and limitations as the project evolves.
- Never add unnecessary complexity or technologies just to make the project look impressive.

## Scope Guardrails

- Do not use real customer data, real company schemas, proprietary business logic, or internal systems.
- Do not mention unrelated real companies.
- Do not imply access to private systems or production data.
- Label all future metrics, source systems, examples, and analysis outputs as simulated.
- Do not add datasets, pipelines, dbt models, dashboards, machine-learning code, notebooks, charts, screenshots, Docker files, or deployment files unless the user explicitly asks for that later stage.

## Review Expectations

Before finishing any future change:

- Confirm the change is consistent with the project charter and decision policy.
- Confirm that management KPIs and diagnostic KPIs are clearly distinguished.
- Confirm that assumptions and limitations are visible.
- Confirm that no result is presented as completed analysis unless the underlying work exists and has been validated.
